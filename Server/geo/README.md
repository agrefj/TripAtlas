# Сервер границ городов (`geo.agstatus.online`)

Приложение берёт границы городов не у публичного nominatim.openstreetmap.org (лимит —
1 запрос в секунду на всё приложение), а у своего сервера. Это тот же
[Nominatim](https://nominatim.org) 5.3.3, но урезанный под единственный запрос приложения:

```
GET /reverse?format=jsonv2&lat=…&lon=…&zoom=10&polygon_geojson=1&polygon_threshold=0.0005
```

## Как устроен

```
приложение ──HTTPS──▶ Cloudflare ──tunnel──▶ cloudflared (ВМ) ──▶ nginx :8088 ──▶ Nominatim :8080
```

- **ВМ на Proxmox:** Debian 13, 8 vCPU, 12 ГБ RAM (для обслуживания хватит 8), диск 320 ГБ
  (thin). Вход только по SSH-ключу. Автообновления безопасности включены.
- **Nominatim** — Docker-образ `mediagis/nominatim:5.3.3`, стиль импорта `admin`, `REVERSE_ONLY`,
  `FREEZE` (без обновлений). База лежит в томе Docker, PostgreSQL наружу не открыт,
  API слушает только `127.0.0.1:8080` ([run_nominatim.sh](run_nominatim.sh)).
- **nginx** ([nginx.conf](nginx.conf)) пропускает только `GET /status` и `GET /reverse` со строкой
  запроса приложения целиком, в её порядке (`format=jsonv2&lat=…&lon=…&zoom=10&polygon_geojson=1&
  polygon_threshold=0.0005`). Другие пути — 404, другие параметры — 400, другие методы — 403.
  Лимит — 30 запросов в секунду с адреса (по `CF-Connecting-IP`, всплеск до 30): приложение шлёт
  до 12 в секунду, по три сразу, так что хватает и двум телефонам в одной сети. В журнал доступа
  пишется только путь, а журнал ошибок (где nginx повторил бы строку запроса) — только критические
  ошибки, так что координат в логах нет.
- **Cloudflare Tunnel** `tripatlas-geo` ([tunnel_setup.sh](tunnel_setup.sh)): входящих портов нет.
  На ВМ лежат только учётные данные самого туннеля (`/etc/cloudflared`), сертификат аккаунта удалён.

## Данные

Из планеты OSM оставляем только то, что нужно запросу `zoom=10`
([make_borders.sh](make_borders.sh), osmium):

- `boundary=administrative` и все `place=*` со всеми их линиями и точками;
- именованные `landuse` семи видов, которые импортирует стиль `admin`, но только с `wikidata`:
  через них Nominatim «привязывает» (прячет) дубли точек-населённых пунктов.

Файл планеты (~96 ГБ) урезается за полчаса примерно до 2 ГБ; импорт идёт около 5 часов,
база занимает около 17 ГБ (сборка ноября 2026 года).

**Проверено** на выгрузках Люксембурга и Бельгии: урезанный сервер отдаёт тот же объект OSM
и ту же GeoJSON-геометрию, что и публичный, в 47 из 47 и 89 из 89 точек
([strict_compare.py](strict_compare.py); `place_id` и `importance` у разных установок разные,
приложение их не читает).

Мировая база (планета на 16 ноября 2026 года) сверена с теми же сохранёнными ответами и ещё
с 65 столицами и крупными городами: совпали 45 из 47, 87 из 89 и 60 из 65 точек. Почти все
отличия — в геометрии тех же объектов, которые поправили в OSM уже после 16 ноября (например,
Бельгию — 19 ноября, Бразилиа — 20 ноября); следующая пересборка их подтянет.

**Известное отличие.** Свежий импорт Nominatim 5.3.3 оставляет непривязанными часть
точек-населённых пунктов, лежащих внутри одноимённой границы того же типа, а публичный сервер
их привязывает. По миру таких мест 124 из 48 469 границ с тегом `place` (0,26 %,
запрос [linkcheck.sql](linkcheck.sql)). Для них сервер отдаёт точку, и приложение рисует
пунктирный круг вместо границы — например, для района Диес-де-Октубре в Гаване. Урезание
планеты тут ни при чём: полный импорт Кубы ведёт себя так же.

## Сборка и обновление

Раз в 6–12 месяцев (границы меняются редко, а приложение хранит найденные границы на
устройстве навсегда):

1. Скачать свежий `planet-latest.osm.pbf` в `/srv/osm` и проверить md5 в `planet-md5.txt`:
   `md5sum -c planet-latest.osm.pbf.md5 > planet-md5.txt`.
2. Собрать новую базу рядом с работающей — в новый контейнер и том на свободном порту:
   `build_world.sh nominatim-2027-05 8081` ([build_world.sh](build_world.sh)): урезать планету,
   импортировать (в ноябре 2026 года всё вместе заняло около 5,5 ч на 8 vCPU и 12 ГБ RAM),
   сверить с сохранёнными ответами публичного сервера.
   Скрипт откажется работать, если такой том уже есть: иначе Docker взял бы старую базу
   и импорт бы не прошёл.
3. Переключить `proxy_pass` в `nginx.conf` на новый порт, `docker restart geo-front`, проверить
   `/status` снаружи.
4. Удалить старый контейнер и его том (`docker rm -f nominatim && docker volume rm nominatim-db`)
   и файл планеты.

Первая установка — `build_world.sh nominatim 8080`.
